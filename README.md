# University FAQ Bot

Telegram-бот — интерфейс к университетской FAQ-системе на основе RAG. Пользователь пишет вопрос обычным сообщением и получает ответ из базы знаний. Администратор через того же бота управляет документами в базе.

---

## Что умеет бот

### Для любого пользователя

**Задать вопрос**
Напишите вопрос обычным сообщением или нажмите кнопку «❓ Задать вопрос». Бот найдёт ответ в базе знаний и вернёт его. Контекст диалога сохраняется — можно задавать уточняющие вопросы подряд, и бот будет понимать о чём речь.

**Оценить ответ**
Под каждым ответом появляются кнопки 👍 и 👎. Оценка отправляется в систему и помогает улучшать качество ответов. Оценить можно только один раз — после нажатия кнопки исчезают. Если ответ слишком старый — бот об этом сообщит.

**Справка**
Команда `/help` показывает список доступных команд и кнопок. Содержимое справки адаптируется под роль пользователя — администратор видит расширенный список.

### Для администратора

Кнопка «📂 Загрузить документ» появляется в меню только у пользователей с нужными правами.

**Загрузить документ в базу знаний**
Нажмите кнопку и отправьте файл. После загрузки бот сообщает ID созданного документа. Если отправить текст вместо файла — бот напомнит что ждёт именно файл и останется в режиме ожидания. Отмена — командой `/start`.

Поддерживаемые форматы: PDF, DOCX, TXT.

---

## Защитное поведение

- Бот проверяет права пользователя через API **до** вызова любого защищённого действия. Если прав нет — отказывает сразу, не обращаясь к бэкенду.
- Заблокированный или неактивный пользователь получает отказ при `/start` и не может пользоваться ботом.
- Права проверяются дважды при загрузке документа — на момент нажатия кнопки и на момент получения файла (на случай если права сменились пока пользователь выбирал файл).
- Если бэкенд недоступен — бот вежливо сообщает об этом вместо того чтобы упасть.
- Кэш прав хранится 60 секунд — бот не делает лишних запросов к API при каждом действии.

## Быстрый старт

```bash
# 1. Создать и активировать виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Заполнить переменные окружения
cp .env.example .env
# открыть .env и вставить BOT_TOKEN и API_BASE_URL

# 4. Запустить
python main.py
```

---

## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота из BotFather |
| `API_BASE_URL` | Адрес бэкенда, например `http://localhost:8000` |

## API бэкенда

Бот общается с REST API через `app/services/api.py`. Все запросы передают заголовок `x-telegram-id` для идентификации пользователя.

| Метод | Путь | Используется для |
|---|---|---|
| POST | `/api/v1/users/sync` | Регистрация пользователя при `/start` |
| GET | `/api/v1/users/by-telegram/{id}` | Получить внутренний ID пользователя |
| GET | `/api/v1/users/{id}/permissions` | Получить список прав пользователя |
| POST | `/api/v1/ask` | Задать вопрос RAG-системе |
| POST | `/api/v1/conversations/messages/{id}/feedback` | Отправить оценку ответа |
| POST | `/api/v1/documents` | Загрузить документ в базу знаний |
